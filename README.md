# مجتمع ICT

منصة عربية تجمع مصادر التعلّم والفرص التقنية في مكان واحد، وتسهّل على أعضاء المجتمع الوصول إلى الدورات والأدوات والموارد الموثوقة.

## أقسام الموقع

- **الدورات:** دورات مجتمع ICT، ومجلدات Google Drive، ودورات من منصات خارجية.
- **أدوات الذكاء الاصطناعي:** أدوات مفيدة مع توضيح التصنيف ونموذج التسعير وتاريخ آخر مراجعة.
- **الموارد التقنية:** شروحات ومقالات وقوالب وروابط مجتمعات ووثائق.
- **الفرص:** وظائف وتدريبات ومنح، مع مواعيد التقديم ومصادر الإعلان.
- **الفعاليات:** لقاءات وورش عمل وفعاليات المجتمع.

## اللغات واتجاه الصفحة

التجربة الأساسية باللغة العربية وباتجاه من اليمين إلى اليسار (`RTL`). يحتوي الهيكل على مسارات وملفات ترجمة تمهيدية للإنجليزية (`/en`) لدعمها لاحقاً. يجب أن يحدد كل مسار لغة الصفحة واتجاهها، وأن تعمل عناصر الواجهة في الاتجاهين.

## التقنية

- Next.js App Router وTypeScript للموقع.
- Tailwind CSS لبناء الواجهة.
- لوحة إدارة عربية محمية بكلمة مرور، مع API داخلي.
- قاعدة بيانات PostgreSQL لتسجيل الأعضاء والجلسات وتخزين المحتوى والروابط والصور بشكل دائم.
- Vercel أو أي استضافة Node.js لنشر تطبيق Next.js.

## حالة المشروع

توجد واجهة عربية/إنجليزية وصفحات للأقسام والبحث والتفاصيل. لوحة `/admin` تحفظ المحتوى والفروع وروابط المجتمعات والصور في قاعدة بيانات PostgreSQL، وتظهر العناصر المنشورة على صفحات الموقع. صفحة `/ar/account` تتيح إنشاء حساب وتفعيل تفضيل تنبيهات الفعاليات. يستطيع المسؤول إرسال الفعاليات المنشورة إلى الأعضاء المشتركين بالتنبيهات عبر Gmail SMTP.

## الهيكل

- `src/app/`: صفحات الموقع ومسارات API.
- `src/components/`: مكونات الواجهة المشتركة.
- `src/features/`: وظائف وواجهات كل قسم من أقسام الموقع.
- `src/lib/`: إعدادات الربط والخدمات والأدوات المشتركة (قاعدة البيانات والمصادقة والبريد).
- `src/messages/`: نصوص الواجهة المترجمة.
- `postgres/`: مخطط قاعدة بيانات PostgreSQL وملفات التهيئة (`schema.sql`).
- `public/`: الصور والأيقونات والخطوط العامة.
- `scripts/`: أدوات صيانة المحتوى وتهيئة قاعدة البيانات (`init-db.ts`).
- `docs/`: أدلة المحتوى والنشر.

## إدارة المحتوى وقاعدة البيانات

لوحة الإدارة على `/admin` تتطلب `ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET` و`DATABASE_URL`.
لتهيئة جداول قاعدة البيانات:
```bash
npm run db:init
```
أو تشغيل محتوى `postgres/schema.sql` في أي واجهة لقاعدة بيانات PostgreSQL.
تخزين الصور يتم مباشرة كبيانات ثنائية داخل جدول `media_assets` في PostgreSQL، دون الحاجة لأي خدمات تخزين سحابية خارجية.

لتفعيل حسابات الأعضاء وتنبيهات الفعاليات، أضف رابط اتصال قاعدة البيانات إلى `DATABASE_URL` في `.env.local`. يختار العضو بنفسه تشغيل تنبيهات الفعاليات من صفحة حسابه. لإرسال فعالية منشورة، أضف `GMAIL_USER` و`GMAIL_APP_PASSWORD` إلى `.env.local`. زر «إرسال الفعالية بالبريد» يظهر في قائمة الفعاليات المنشورة بلوحة الإدارة؛ تُرسل الرسائل منفصلة للمشتركين أصحاب البريد المؤكد، ويُحفظ سجل يمنع إعادة الإرسال لمن وصلته. لا ترفع `.env.local` إلى GitHub؛ استخدم `.env.example` كقالب بلا أسرار.

## التشغيل المحلي

يتطلب المشروع Node.js 20.9 أو أحدث. انسخ `.env.example` إلى `.env.local`، وضع كلمة مرور خاصة في `ADMIN_PASSWORD` وسراً عشوائياً بطول 32 حرفاً أو أكثر في `ADMIN_SESSION_SECRET`، ورابط قاعدة البيانات في `DATABASE_URL`.
شغّل الأوامر التالية:
```bash
npm install
npm run db:init
npm run dev
```
ثم افتح `http://localhost:3000/ar`. قبل النشر يمكنك تشغيل:
```bash
npm run lint
npm run typecheck
npm run build
```

## رفع الكود إلى GitHub

أنشئ مستودعًا فارغًا على GitHub، ثم من مجلد `web` نفّذ الأوامر التالية بعد استبدال الرابط برابط مستودعك:

```powershell
git add .
git status --short
git commit -m "Migrate database from Supabase to PostgreSQL"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

قبل `git commit`، تأكد أن `.env.local` غير موجود ضمن الملفات المرحّلة؛ الملف مستثنى في `.gitignore`. ارفع `.env.example` فقط بعد التأكد أنه لا يحتوي قيمًا سرية. لا ترفع `node_modules/` أو `.next/` أو ملفات السجل.

خطوات النشر على Vercel وإعداد متغيرات البيئة موجودة في `docs/deployment-vercel.md`.

## ملاحظات للمساهمين

- اكتب نصوص الواجهة في ملفات الترجمة بدلاً من تثبيتها داخل المكونات.
- اجعل المكونات قابلة للاستخدام بالعربية والإنجليزية، ولا تفترض اتجاه الواجهة داخل التنسيقات.
- أضف لكل مورد رابطاً ومصدراً واضحين، وبيانات كافية لمراجعته لاحقاً.
- لا تضع مفاتيح أو أسراراً في ملفات المشروع؛ استخدم متغيرات البيئة.
