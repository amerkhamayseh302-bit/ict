# مجتمع ICT

منصة عربية تجمع مصادر التعلّم والفرص التقنية في مكان واحد، وتسهّل على أعضاء المجتمع الوصول إلى الدورات والأدوات والموارد الموثوقة.

## أقسام الموقع

- **الدورات:** دورات مجتمع ICT، ومجلدات Google Drive، ودورات من منصات خارجية.
- **أدوات الذكاء الاصطناعي:** أدوات مفيدة مع توضيح التصنيف ونموذج التسعير وتاريخ آخر مراجعة.
- **الموارد التقنية:** شروحات ومقالات وقوالب وروابط مجتمعات ووثائق.
- **الفرص:** وظائف وتدريبات ومنح، مع مواعيد التقديم ومصادر الإعلان.
- **الفعاليات:** لقاءات وورش عمل وفعاليات المجتمع.

## اللغات واتجاه الصفحة

التجربة الأساسية باللغة العربية وباتجاه من اليمين إلى اليسار (`RTL`). يحتوي الهيكل على مسارات وملفات ترجمة تمهيدية للإنجليزية (`/en`) لدعمها لاحقاً. يجب أن يحدد كل مسار لغة الصفحة واتجاهها، وأن تعمل عناصر الواجهة في الاتجاهين.

## التقنية المقترحة

- Next.js App Router وTypeScript للموقع.
- Tailwind CSS وshadcn/ui لبناء الواجهة.
- لوحة إدارة عربية محمية بكلمة مرور، مع API داخلي وملفات JSON محلية.
- Supabase عند الحاجة إلى حسابات أعضاء أو ميزات تعتمد على المستخدم.
- Vercel لاستضافة الموقع ومعاينة التغييرات.

## حالة المشروع

توجد واجهة عربية/إنجليزية وصفحات للأقسام والبحث والتفاصيل. لوحة `/admin` تحفظ المحتوى والفروع والصور عبر API داخلي محمي في مجلد `data/` على الخادم، وتظهر العناصر المنشورة على صفحات الموقع. صفحة `/ar/account` تتيح إنشاء حساب وتفعيل تفضيل تنبيهات الفعاليات باستخدام Supabase. يستطيع المسؤول إرسال الفعاليات المنشورة إلى الأعضاء الذين أكدوا بريدهم واشتركوا بالتنبيهات، عبر Gmail SMTP.

المشروع جاهز لرفع **الكود المصدري** إلى GitHub، لكن GitHub وحده لا يشغّل تطبيق Next.js. كما أن الكتابة إلى `data/` والتخزين المحلي للصور يحتاجان قرصًا دائمًا؛ قبل نشر الموقع على منصة بقرص مؤقت أو للقراءة فقط، يجب نقل المحتوى والصور إلى قاعدة بيانات وتخزين دائم مثل Supabase Storage.

## الهيكل

- `src/app/`: صفحات الموقع ومسارات API.
- `src/components/`: مكونات الواجهة المشتركة.
- `src/features/`: وظائف وواجهات كل قسم من أقسام الموقع.
- `src/lib/`: إعدادات الربط والخدمات والأدوات المشتركة.
- `src/messages/`: نصوص الواجهة المترجمة.
- `public/`: الصور والأيقونات والخطوط العامة.
- `scripts/`: أدوات صيانة المحتوى والروابط.
- `docs/`: أدلة المحتوى والنشر.

## إدارة المحتوى

لوحة الإدارة على `/admin` تتطلب المتغيرين `ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET` في `.env.local`. المحتوى محفوظ في `data/content.json`، والفروع في `data/categories.json` (يُنشأ عند حفظ الفروع)، والصور في `data/uploads/`. احتفظ بنسخة احتياطية من مجلد `data/`؛ التخزين على القرص مناسب للتشغيل المحلي أو لخادم يوفّر قرصاً دائماً، وقد يُمسح أو يمنع الكتابة على منصات الاستضافة ذات الملفات المؤقتة. يجب التحقق من الروابط والأسعار والمواعيد قبل نشر المحتوى. روابط Google Drive تبقى روابط خارجية؛ لا تُنسخ الملفات إلى الموقع إلا بإذن واضح لإعادة نشرها.

لتفعيل حسابات الأعضاء، أضف عنوان مشروع Supabase ومفتاح النشر إلى `.env.local`، ثم شغّل ملف `supabase/migrations/202610250001_event_subscriptions.sql` من SQL Editor في Supabase. أضف عنوان الموقع المحلي إلى قائمة Redirect URLs لتأكيد البريد. يختار العضو بنفسه تشغيل تنبيهات الفعاليات من صفحة حسابه. لإرسال فعالية منشورة، أضف `SUPABASE_SECRET_KEY` و`GMAIL_USER` و`GMAIL_APP_PASSWORD` إلى `.env.local`، ثم شغّل محتوى `docs/event-email-dispatch.sql` في SQL Editor. زر «إرسال الفعالية بالبريد» يظهر في قائمة الفعاليات المنشورة بلوحة الإدارة؛ تُرسل الرسائل منفصلة للمشتركين أصحاب البريد المؤكد، ويُحفظ سجل يمنع إعادة الإرسال لمن وصلته. لا ترفع `.env.local` إلى GitHub؛ استخدم `.env.example` كقالب بلا أسرار.

## التشغيل المحلي

يتطلب المشروع Node.js 20.9 أو أحدث ويستخدم `pnpm` (يوجد ملف `pnpm-lock.yaml`). انسخ `.env.example` إلى `.env.local`، وضع كلمة مرور خاصة في `ADMIN_PASSWORD` وسراً عشوائياً بطول 32 حرفاً أو أكثر في `ADMIN_SESSION_SECRET`. في PowerShell على Windows شغّل `corepack.cmd pnpm install` لتثبيت الحزم، ثم `corepack.cmd pnpm dev` لتشغيل الموقع وافتح `http://localhost:3000/ar`. بعد تثبيت الحزم يمكنك تشغيل `corepack.cmd pnpm lint` و`corepack.cmd pnpm typecheck` و`corepack.cmd pnpm build` قبل النشر.

## رفع الكود إلى GitHub

أنشئ مستودعًا فارغًا على GitHub، ثم من مجلد `web` نفّذ الأوامر التالية بعد استبدال الرابط برابط مستودعك:

```powershell
git add .
git status --short
git commit -m "Prepare ICT Community website"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

قبل `git commit`، تأكد أن `.env.local` غير موجود ضمن الملفات المرحّلة؛ الملف مستثنى في `.gitignore`. ارفع `.env.example` فقط بعد التأكد أنه لا يحتوي قيمًا سرية. لا ترفع `node_modules/` أو `.next/` أو ملفات السجل.

رفع الكود إلى GitHub يحفظ المصدر فقط؛ لا ينشر الموقع ولا ينقل بيانات قاعدة Supabase أو إعدادات Gmail تلقائيًا. عند اختيار الاستضافة لاحقًا، أضف متغيرات البيئة في إعدادات منصة الاستضافة، وحدّث `NEXT_PUBLIC_SITE_URL` إلى رابط الموقع العام.

## ملاحظات للمساهمين

- اكتب نصوص الواجهة في ملفات الترجمة بدلاً من تثبيتها داخل المكونات.
- اجعل المكونات قابلة للاستخدام بالعربية والإنجليزية، ولا تفترض اتجاه الواجهة داخل التنسيقات.
- أضف لكل مورد رابطاً ومصدراً واضحين، وبيانات كافية لمراجعته لاحقاً.
- لا تضع مفاتيح أو أسراراً في ملفات المشروع؛ استخدم متغيرات البيئة.
