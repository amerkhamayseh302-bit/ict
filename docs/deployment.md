# التشغيل المحلي وتجهيز المشروع للنشر

## المتطلبات

- Node.js 20.9 أو أحدث، بحسب متطلبات Next.js 16.
- قاعدة بيانات PostgreSQL (محلية أو سحابية مثل Neon أو Railway أو غيرها).
- مدير الحزم pnpm أو npm.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env.local` وعدّل القيم التي تستخدمها (بما فيها `DATABASE_URL`).
2. نفّذ `pnpm install` أو `npm install` لتثبيت الاعتماديات.
3. لتجهيز جداول قاعدة البيانات، نفّذ:
   ```bash
   npm run db:init
   ```
4. نفّذ `npm run dev` ثم افتح `http://localhost:3000/ar`.
5. بعد تعديل الموقع، استخدم `npm run lint` و`npm run typecheck`، ثم `npm run build` قبل النشر.

## لوحة الإدارة والتخزين

تفتح لوحة الإدارة من `/admin`. تضيف العناصر وتعدّلها وتحذفها وتبدّل حالتها عبر API داخلي محمي. يتم حفظ المحتوى والفروع والصور وروابط المجتمع والأعضاء بأمان داخل قاعدة بيانات PostgreSQL.

## النشر

رفع المصدر إلى GitHub يحفظ الكود فقط ولا يشغّل الموقع. أنشئ مستودعًا على GitHub وارفع ملفات المشروع من مجلد `web`، مع عدم رفع `.env.local` أو `node_modules/` أو `.next/` أو ملفات السجل.

قبل إطلاق الموقع، اختر استضافة تدعم Next.js Node API routes (مثل Vercel أو Node.js Server). بعد اختيار الاستضافة:

1. أضف متغيرات `.env.example` إلى إعدادات بيئة المعاينة والإنتاج، مع قيم حقيقية وآمنة (مثل `DATABASE_URL` و`ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET`).
2. اضبط `NEXT_PUBLIC_SITE_URL` على النطاق النهائي لاستخدامه في الروابط وبيانات الموقع وخريطة الموقع.
3. انشر معاينة، وراجع صفحات RTL وLTR وتسجيل الدخول وروابط الصفحات على الهاتف، ثم انشر للإنتاج.

## الاسترجاع والتحديث

- احتفظ بنسخة احتياطية منتظمة من قاعدة بيانات PostgreSQL.
- راجع صلاحية روابط الموارد والفرص بشكل دوري.
- لا تضع كلمات المرور أو أسرار الجلسة أو بيانات الاعتماد في GitHub؛ استخدم دائمًا إعدادات البيئة في منصة الاستضافة.
