# التشغيل المحلي وتجهيز المشروع للنشر

## المتطلبات

- Node.js 20.9 أو أحدث، بحسب متطلبات Next.js 16.
- pnpm لإدارة الحزم.
- يعتمد المحتوى والصور التي تعدّلها لوحة الإدارة على ملفات محلية داخل `data/`.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env.local` وعدّل القيم التي تستخدمها.
2. نفّذ `pnpm install --frozen-lockfile` لتثبيت الاعتماديات من ملف القفل الموجود.
3. نفّذ `pnpm dev` ثم افتح `http://localhost:3000/ar`.
4. بعد تعديل الموقع، استخدم `pnpm lint` و`pnpm typecheck`، ثم `pnpm build` قبل النشر.

## لوحة الإدارة والتخزين

تفتح لوحة الإدارة من `/admin`. تضيف العناصر وتعدّلها وتحذفها وتبدّل حالتها عبر API داخلي محمي، وتحفظ المحتوى والفروع والصور في `data/` على قرص الخادم. يلزم قرص دائم قابل للكتابة ونسخ احتياطية للاحتفاظ بهذه التغييرات. GitHub Pages لا يشغّل Next.js API routes، كما أن أنظمة الملفات المؤقتة أو للقراءة فقط لا تحفظ تعديلات اللوحة والصور. قبل استخدام هذه الميزات على استضافة كهذه، انقل المحتوى إلى قاعدة بيانات والصور إلى تخزين دائم مثل Supabase.

## النشر

رفع المصدر إلى GitHub يحفظ الكود فقط ولا يشغّل الموقع. أنشئ مستودعًا على GitHub وارفع ملفات المشروع من مجلد `web`، مع عدم رفع `.env.local` أو `node_modules/` أو `.next/` أو ملفات السجل.

قبل إطلاق الموقع، اختر استضافة تدعم Next.js API routes. إذا اخترت منصة ملفاتها مؤقتة أو غير قابلة للكتابة، انقل تخزين لوحة الإدارة والصور من `data/` إلى خدمة دائمة مثل Supabase. بعد اختيار الاستضافة:

1. أضف متغيرات `.env.example` إلى إعدادات بيئة المعاينة والإنتاج، مع قيم حقيقية وآمنة.
2. اضبط `NEXT_PUBLIC_SITE_URL` على النطاق النهائي لاستخدامه في الروابط وبيانات الموقع وخريطة الموقع.
3. أضف رابط الإنتاج إلى إعدادات Redirect URLs في Supabase.
4. انشر معاينة، وراجع صفحات RTL وLtr وتسجيل الدخول وروابط الصفحات على الهاتف، ثم انشر للإنتاج.

## الاسترجاع والتحديث

- احتفظ بملف القفل الذي ينشئه pnpm مع تغييرات الاعتماديات.
- احتفظ بنسخة احتياطية من مصادر المحتوى قبل تعديلها.
- راجع صلاحية روابط الموارد والفرص بشكل دوري.
- لا تضع مفاتيح Supabase السرية أو كلمة مرور تطبيق Gmail في GitHub؛ استخدم إعدادات البيئة في منصة الاستضافة.
